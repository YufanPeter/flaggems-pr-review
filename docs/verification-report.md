## 3. 排序规则验证

### 3.1 FlagGems 使用的规则

**发现**：FlagGems 使用**纯字母序（字典序）**排序

```python
# ASCII 值决定顺序
数字 (0-9)     → ASCII 48-57
大写字母 (A-Z)  → ASCII 65-90
下划线 (_)     → ASCII 95
小写字母 (a-z)  → ASCII 97-122
```

### 3.2 实际排序示例

```python
# ✅ 正确的 FlagGems 排序
[
    "__ilshift__",          # 双下划线前缀
    "_fused_adam",          # 单下划线前缀
    "_fused_adam_",         # inplace 版本
    "abs",                  # 基础版本
    "abs_",                 # inplace 版本
    "add",
    "add_",
    "addmm",
    "addmm_",
    "addmm_dtype",
    "addmm_dtype_out",
    "addmm_out",            # out 版本
]

# ✅ 为什么这个顺序正确？
"add" < "add_"              # 前缀规则
"add_" < "addmm"            # "_" < "m"
"addmm" < "addmm_"          # 前缀规则
"addmm_" < "addmm_dtype"    # "_" < "_d"
"addmm_dtype" < "addmm_dtype_out"  # 前缀规则
"addmm_dtype_out" < "addmm_out"    # "_d" < "_o"
```

### 3.3 常见错误模式

从 FlagGems 真实代码中发现的错误：

| 错误模式 | 示例 | 原因 |
|---------|------|------|
| out 在 _ 前 | `hardsigmoid_out` > `hardsigmoid_` | `o` > `_` |
| 下划线在数字后 | `log_` > `log10` | `_` > `1` |
| flash 拼写错误 | `flatten` > `flash_attention_backward` | `t` > `s` |

### 3.4 "out 在 inplace 前" 异常的根因分析（git 历史证据）

在全部 **29 个**同时有 inplace(`_`) 和 out(`_out`) 变体的算子族中：
- **26 个**遵循字母序（`_` 在前）✅
- **只有 3 个**违反：`gcd`、`hardsigmoid`、`hypot`

**关键结论**：这 3 个不是 FlagGems 的隐藏排序约定，而是**分两次提交、第二次插错位置**导致的历史遗留 bug。

git 历史证据：

| 算子 | `_out` 引入 PR | 当时 `_` 是否存在 | `_` 后续引入 PR |
|------|---------------|------------------|----------------|
| gcd | #2897 | ❌ 不存在 | #3521 |
| hardsigmoid | #2681 | ❌ 不存在 | #5149 |
| hypot | #2681 | ❌ 不存在 | #5157 |

`_out` 变体最早引入时，对应的 inplace `_` 变体尚不存在，那时 `base → base_out` 是完全正确的字母序。后续 PR（如 #3521 加 `gcd_`）把 inplace 变体**追加到了 `gcd_out` 之后**而非插入到 `gcd` 与 `gcd_out` 之间，才造成乱序：

```
PR #3521 插入 gcd_ 后的实际结果：
  - id: gcd
  - id: gcd_out    ← 早先就在这
  - id: gcd_       ← 新增，被追加到 out 之后（错位）
```

**对工具的意义**：纯字母序检查会把这 3 个标为违规，这是**正确行为**（真实 bug），不是误报。26:3 的压倒性比例证明字母序才是意图的规则。

## 4. 为什么简单的字母序比较是正确的？

### 4.1 不需要特殊的 out/inplace 规则

PyTorch 的命名约定天然符合字母序：

```python
# PyTorch 约定
base_name       # 基础版本
base_name_      # inplace 版本（修改输入）
base_name_out   # out 版本（写入 out 参数）

# 字母序自动正确
"base_name" < "base_name_" < "base_name_out"
```

### 4.2 前缀规则的天然优势

Python 字符串比较的前缀规则使得相关函数自然分组：

```python
"add"           # 分组起点
"add_"          # 同组
"add_out"       # 同组
"addbmm"        # 新分组
```
